## 1. cswap 站点栅格

### 1.1 三族与每站点成本

`cswap` 在 kickmix 里的定价是 **1 T / 每个 bit pair**，与宽度严格成正比：

```
cswap 宽度 → T:  1→1  2→2  4→4  8→8  12→12  16→16  64→64  892→892   （src/e8/e8_price.py）
cx / swap / 无条件 rotate → 0 T；ccx → 1 T
```

三条 `cswap` 调用点都在 `_synchronized_eea` / `sweep_positions` 里（`data/verifiers/dqi/dqi_reference_circuit.py`），
且都**与 `m_chien` 无关**，因此站点栅格在全 `m` 上同构：

| 族 | 调用点 | 宽度 | 每次调用 | 每 (pass,it) 调用数 | 栅格 | 站点 T |
|---|---|---|---|---|---|---|
| **A** | `builder.cswap(swap_ctrl, lhs, rhs)` | 892（含 16 位元数据） | 1 | 1 | `(2, 222)` = 444 | **892** |
| **B** | `builder.cswap(do_shift, reg_b[i-1], reg_b[i])` | 12 | 72 | 72 | `(2, 222, 72)` = 63,936 | **12** |
| **C** | `builder.cswap(swaps[0] 或 both, q_i, reg_a[i])` | 12 | ≤1 | ≤1 | `(2, 222, 73)` = 32,412（**发射 27,300**） | **12** |

控制位分别是 `swap_ctrl`（= `c3_hc & flag`）、`do_shift`、`swaps[0]`/`both`。
**冻结语义**：某站点被冻结 ⟺ 该控制位在所有官方样点上恒为 `|0>`，此时这次 `cswap` 在样点上
就是恒等操作，可以直接删掉——不改变电路在该样点上的任何输出。

### 1.2 三个互相独立的定价口径，结论一致

| 口径 | 方法 | A | B | C | 合计 |
|---|---|---|---|---|---|
| E5 解析 | 调用形态 × 宽度 | 396,048 | 383,616 | —（未做） | 779,664 |
| 源码替换消融 | 删掉该族全部 cswap 后重测 T（m=280） | −396,048 | −383,616 | −327,600 | −1,107,264 |
| **census ∩ freeze 审计** | 逐 (pass,it,i) 发射普查 ∩ 冻结掩码（m=4095） | −53,520 | −12,960 | −289,128 | **−355,608** |

三者互不共享代码路径（消融改源码文本、审计数发射记录、E5 数调用），
且**审计预测的 ΔT 与真实重建的 T 差值完全相等**：

```
build/e8/dqi_cswap.kmb   T = 5,725,461 − 355,608 = 5,369,853   ← 实测
```

→ `notes/runs/e8/price_m280.json`、`notes/runs/e8/audit_cswap.json`

### 1.3 C 族的 2,556 个"幽灵站点"

`sweep_positions` 的两条分支是：

```python
if len(swaps) == 1:      builder.cswap(swaps[0], q_i, reg_a[i])
elif swaps:              builder.cswap(both, q_i, reg_a[i])
```

`swaps` 是 Python 层列表，**有时为空** ⇒ 该 (it,i) 根本不发射 `cswap`，但它在栅格里占一个站点。
普查（`census`）实测：每趟 16,206 个候选站点中只有 **13,650** 个真正发射；
冻结掩码里含全部 2,556 个幽灵站点（探针恒读到 0），它们**省不下 T**。
报告所有"有效站点"数字都已扣掉这 2,556，避免把 2,556 × 12 × 2 = 61,344 T 的虚账算进去。

## 2. 仪器（为什么不能用 E7 的闭式，以及怎么保证两趟等价）

### 2.1 直接探针 vs 闭式

E7 冻结 mul 用的是**闭式**（`e6d_schedule.mul_bitmap`，从元数据轨迹反推 `mul` 位）。
cswap 的三个控制位**没有**现成闭式：`swap_ctrl = c3_hc & flag`、`swaps` 依赖 `n_q` 且带一块
Python 条件分支。所以本轮改用**源码级直接探针**：在 `cswap` 发射前把控制位读到专用探针辅助位。

`src/e8/e8_src.py` 做的是**文本级源码替换**（不是 monkeypatch 类方法），注入：

* `_e8_frozensite(self, kind, it, i)`：冻结闸，插在三处发射点前；
* `_e8_probe_reg(self, kind, it, i)`：探针读取点；
* `_e8_alloc_probe`：构建时按需分配探针辅助位（只在 `dec.e8_probe_enabled` 时）；
* `_e8_census`：普查发射。

探针位插在 `if not is_adjoint and multiplies:` **之前**（adjoint 调用点之前也一样），
中间只隔着 `cswap` 块，不触碰 `mul`，因此两趟读到的都是乘法器真正消费的那个值。

### 2.2 forward-only 探针电路

`e8_probe.build_probe(n, degree)`：从 `with builder.mark('chien_forney_mbuc'):`
截断到第一个 `builder.free(reg)` —— 只保留一次 EEA（含 222 个 `it`），
**两趟控制位图逐位相同**（§2.3）所以只需一趟。

| | Q | T | instructions | 构建 | 102,400 发 |
|---|---|---|---|---|---|
| 参考电路（m=280） | 1,893 | 4,386,396 | 41,687,083 | 3.6 s | — |
| forward-only 探针（含 48,618 探针位） | 66,717 | 2,140,362 | 19,293,837 | ~5 s | **75 s** |
| 两趟全探针 | 99,129 | 4,386,396 | 41,887,827 | 12.7 s | 172 s |

探针读取用 `sim.read_across_shots(array)` → (站点数 × 发数) 的 numpy 位图，
2,000 个量子比特 0.45 ms，所以"一发 102,400 点的并集"只要 75 s。

### 2.3 两趟镜像检查（E7 只对 mul 做过，本轮对三族都做）

`src/e8/e8_mirror.py` 在**完整** decoder（两趟都跑）上分别读 forward / adjoint 探针：

| shots | swap | shift | sweep | forward-only | adjoint-only |
|---|---|---|---|---|---|
| 512 | 71 = 71 | 10,400 = 10,400 | 606 = 606 | 0 | 0 |
| 16,384 | 147 = 147 | 15,256 = 15,256 | 1,135 = 1,135 | 0 | 0 |

48,618 个站点 × 16,384 发**零分歧** ⇒ 一趟测出的并集可以安全地套到两趟上。

### 2.4 mul 探针 vs E7 闭式：逐位一致

`src/e8/e8_mulcheck.py` 在 `dqi_fp2` 的官方样点（16,384 发）上同时跑两种仪器：

```
direct probe union = 14,636   closed-form union = 14,636   identical = True
direct-only = 0   closedform-only = 0
```

⇒ 新仪器与 E7 的仪器在同一个问题上同答案，叠加时不会出现"两把尺子"。

### 2.5 E7 mul 冻结的**位级复现**（仪器等价性的硬证据）

E7 的不动点没有落盘最终掩码。本轮从 `notes/runs/e7/union_acc.npy`（307,200 发种子）
∪ `sample(sha(dqi_fp0.kmb))` ∪ `sample(sha(dqi_fp1.kmb))` 重建：


## 3. 样点并集与不动点

### 3.1 官方样点的种子是 artifact 自己的 sha

`verify_submission_dqi.py`：`seed = int(sha256(电路文件), 16)`（`--salt` 默认空）。
**任何一次重建都会换掉整个 102,400 发样点**，所以"掩码 → 重建 → 样点变 → 掩码失效"
必须用不动点迭代收敛，而不是算一次。

### 3.2 单样点并集（基线）

在 sha `3dfcad7b…`（= E7 已提交 artifact）的官方样点上的一次 102,400 发并集
（`notes/runs/e8/probe_fp2_102400.json`，每趟）：

| 族 | 点亮 | 可冻 | 可冻 T / 趟 |
|---|---|---|---|
| swap | 152 / 222 | 70 | 62,440 |
| shift | 15,308 / 15,984 | 676 | 8,112 |
| sweep | 1,218 / 16,206 | 14,988 | 179,856 |
| 合计 | — | 15,734 | 250,408（两趟 500,816） |

### 3.3 并集的生长曲线：它是不是饱和？

不动点的终点 = 栅格 − **支撑集**（官方分布下"至少被点亮一次"的站点集合），
单样点并集会低估支撑集，所以每一轮都会侵蚀一点。为了看清侵蚀会不会失控，
先做了一次纯测量（`e8_union_trend.py`，16 × 25,600 发 = 409,600 发独立样点）：

| 样点 # | 该样点点亮 sweep | 累计并集 sweep | 新增 |
|---|---|---|---|
| 0–6 | 1,176 → 1,153 | 1,176 → 1,284 | 58, 5, 36, 6, 3, 0 |
| 7–11 | 1,124 → 1,041 | 1,310 → 1,348 | 26, **0**, 22, 8, 8 |
| 12–15 | 1,188 → 1,064 | 1,348 → 1,350 | **0, 0, 0, 2** |

**最后 4 个独立样点里 3 个一个新站点都没加** ⇒ 并集确实在饱和，
支撑集就在累计并集附近（sweep ≈ 1,600、shift ≈ 15,450、swap ≈ 190）。

`swap` 族是唯一"细尾"的：单样点点亮 ~150，累计到 ~190，还在缓慢爬。
它的支撑集接近 222，可冻圣地只有 30 个（§1 表）。

### 3.4 不动点轨迹（`build/e8b/cswap_fixpoint.json`）

种子并集 = `union_fp2` ∪ 第一轮不动点最终并集 ∪ 生长曲线并集（≈110 万发累计），
之后每轮：构建 → 用**该 artifact 自己的官方样点**探针 → 命中冻结站点就解冻 → 重建。

| round | freeze swap/shift/sweep | T | viol_shots | viol_sites | new_sites |
|---|---|---|---|---|---|
| 0 | 33 / 540 / 14,608 | 5,364,381 | 2 | 2 / 0 / 0 | 2 |
| 1 | 31 / 540 / 14,608 | 5,367,949 | 1 | 1 / 0 / 0 | 1 |
| 2 | 30 / 540 / 14,608 | 5,369,733 | 3 | 0 / 0 / 5 | 5 |
| **3** | **30 / 540 / 14,603** | **5,369,853** | **0** | 0 / 0 / 0 | **0** |

→ **第 3 轮收敛**：`viol_shots = 0` 表示该 artifact 自己的 102,400 发样点里
**没有任何一发点亮任何被冻结的控制位**。

一个早先的、种子较弱的轮次（`logs/e8_fixpoint.log`，8 轮未收敛）把侵蚀的形状交代得更清楚：

```
swap   70 → 61 → 61 → 54 → 54 → 41 → 38 → 37     （+34 个新点亮）
shift 676 → 651 → 651 → 642 → 639 → 627 → 624
sweep 14,988 → 14,901 → 14,900 → 14,866 → 14,810 → 14,667 → 14,649 → 14,646
```

——侵蚀不是单调衰减，而是被**极少数"偏离发"**驱动：一发偏离会在几十个 `it` 上
同时点亮 `sweep` 站点（日志里 `viol_shots = 8` 却带来 `viol_sites.sweep = 143`）。
这正是 E7 说的"样点级并集饱和、调度级闭包不饱和"的同一现象的 cswap 版本。

### 3.5 收敛后就不再动

`freeze swap=30 shift=540 sweep=14,603` 这组数字**在同一 artifact 的样点上是自洽的**：
把掩码、样点、artifact 三者当成一个方程组，第 3 轮满足 `样点点亮 ∩ 掩码 = ∅`。
复现该 artifact（`build/e8/dqi_cswap.kmb`）得到**相同的 sha**
（`3a7154ab…`，见 `notes/runs/e8/build_cswap.json`）⇒ 样点不变 ⇒ 结论不变，可重复验证。

## 5. 叠加（superposition）：该不该叠在已提交的 mul 冻结上？

### 5.1 结论

**必须叠加，而且要重新跑一次联合不动点；不要独立做两份 artifact。**

三个理由：

1. **分数是同一个电路的同一个 T，而且省下的 T 是相加不是相乘。**
   `score / T_mean` 在三个点上完全一致（4,268,821.12137，
   见 `dqi_fp2` / `dqi_cswap` / `dqi_stacked` 三次实测），所以 score ∝ T。
   两份冻结动的是**不相交**的门集合，因此

   ```
   T_stack = T_ref − Δ_mul − Δ_cswap
   5,161,503 = 5,725,461 − 208,350 − 355,608      ← 静态，逐位吻合
   ```

   （用"比例相乘"会算错：`1.037766 × 1.066227 = 1.106514 ≠ 1.108478`，
   因为两个比例都是相对同一个 `T_ref` 定义的。）
2. **两份冻结互不冲突，站点空间不相交。** mul 冻结的是 `_multiply_and_add_or_sub`
   里两处 `ixor_gf2_mul(..., control=mul)`；cswap 冻结的是同一个 EEA 里的三族 `cswap`。
   两者改的是不同调用点，且 §2.4 已经证明两把尺子在同一个 `(it,i)` 网格上同答案。
3. **但 sha 变了 ⇒ 样点全变 ⇒ 两份掩码都必须在新样点上重新自证。**
   `dqi_fp2` 的 1,391 个 mul 站点是在**它自己的**样点上验证的；一旦叠上 cswap 生成新文件，
   样点整批换掉，E7 的验证**不再覆盖**新文件。E7 自己估计过：新样点平均会点亮
   1–2 个原本冻结的 mul 站点（≈0–1 个真错），足以让 R 动。所以**叠加后必须重跑不动点**，
   而且必须是 mul + cswap **四族联合**的不动点（否则 mul 侧会带着"未自证的假设"提交）。

## 7. 诚实边界

1. **不动点的"零命中"是样品级保证，不是分布级保证。** 它证明的是
   "这 102,400 发官方样点里没有一发点亮被冻结的控制位"。
   若官方评分改用 `--salt`（种子 = `sha256(hash + salt)`），样点会变，
   本轮 `swap` 族（可冻 30/222，细尾）风险最高：新样点很可能点亮其中 1–2 个站点。
   E7 已经实测过"本地样点 = 官方样点"（`logs/e7_verify_fp2.log` 的 R 逐位相同），
   所以默认无 salt；但这是**需要持续盯住的前提**。
2. **侵蚀不会归零。** `sweep` 族单样点点亮 ≈1,300、支撑集 ≈1,600，
   所以即便把并集推到极限，可冻也只有 ≈14,500/趟（不是 16,206）。
   本轮收敛值 14,603 已经贴着这个界，继续迭代只会掉 T。
3. **`swap` 族已接近枯竭。** 222 个站点里只有 30 个（13.5%）可冻，
   剩下 192 个在官方分布下会被点亮。想再榨这块，只能改电路结构
   （E5 已证"无条件化" 512/512 失败），不是在冻结层面能解决的。
4. **本轮没有提交，配额消耗 0。** 冻结掩码、artifact、全部原始数据都在本地，
   随时可用 `e8_build.py` 重建并校验 sha。
5. **叠加结论（§5）已经不是外推，而是实测**：四族联合不动点 2 轮收敛，
   `build/e8/dqi_stacked.kmb` 全量 102,400 发 PASS、R / eps+ 逐位相同。
   唯一仍需留意的前提是 **mul 侧也换了样点**：本轮两个新样点都没命中 E7 的
   1,391 个站点，但这是一次好的抽样结果，不是数学保证；
   提交前若再重建（哪怕只改一个无关字节），**样点会全换，必须重跑不动点**。
6. **`swap` 族的细尾风险要单独记住**：它是三族里唯一"每轮还在掉站点"的
   （30 → 28），也是唯一在换样点后最容易命中的。若官方加 salt，
   最先失效的就是它（最多 ≈50,000 T，占全电路 0.9%），
   `shift`/`sweep`/`mul` 的支撑集都已经被多轮独立样点压得很实。
