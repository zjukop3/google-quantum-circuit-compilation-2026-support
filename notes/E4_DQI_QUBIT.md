## 0. TL;DR —— 三条必须先说的结论

1. **「reg_b 的 876 位是 Proos–Zalka 无脑 padding，可以用更紧凑的表示换掉」——被实测证伪。**
   把每个 `reg_a`/`reg_b` 系数槽的**逐迭代占用**打出来（DEBUG_PRINT 探针，零额外量子比特）：

   | n | m_e = n+3 | 固定槽位 2·m_e | `nnz_a` 均值/最大 | `nnz_b` 均值/最大 | 打包下界 `max(nnz_a+nnz_b)` | 占用率 |
   |---|---|---|---|---|---|---|
   | 10 | 13 | 26 | 12.14 / 13 | 10.02 / 12 | 24 | 92.3% |
   | 20 | 23 | 46 | 22.22 / 23 | 19.97 / 22 | 44 | 95.7% |
   | 40 | 43 | 86 | 42.26 / 43 | 39.95 / 42 | 84 | 97.7% |
   | **70** | **73** | **146** | **72.29 / 73（99.0%）** | **69.89 / 72（95.7%）** | **144** | **98.6%** |

   **两个多项式数组在整个 222 次前向 EEA 里几乎 100% 密实。** 一个任意紧凑的打包布局最多
   回收 **2 个槽位 = 24 量子比特 = Q 的 1.27%**。876 位不是副本、不是每轮余数留存、不是 padding
   —— 它就是 EEA 的**第二个（辅助）多项式本身**，而它对偶地、在收尾时正好又是 σ(36 字)+ω(35 字)。
   **攻击 reg_b 的收益上限是 ×1.026（score），不是 1.7×。**

2. **Q 的真实可用余量是 5%–10%，不是 30%。** 见 §5.3 的下界论证：
   任何「物化出 σ 与 ω」的可逆解码器 Q ≥ 840 + 852 = **1692**（S 的 840 位是契约硬底线，
   σ/ω 共 71 个字）。参考实现 1893 只比这个硬底线高 **11.9%**；把它榨干是 score **×1.252**。
   **用户设想的 Q≈1325 需要把 ω 整个消掉（840+36×12=1272），
   那是换 key-equation 求解器 + Chien/Forney 的重写，不是「瘦身」；而且现在 ω 的求值是
   0-T 的常数乘法，换成在线卷积后很可能净亏（§5.3）。**

3. **四条点名路线里，只有 (c) 真的碰得到 Q，而且被 kickmix API 卡死。**
   Q=1893 由**一个瞬态**设定：前向 EEA 里 `accumulate_quotient` 的
   `init_gf2_div_with_scaffold`（72 位 = quotient 12 + scaffold 60），叠加在 1803 位常驻宽度上。
   实测：换成不留 scaffold 的 `init_gf2_div` → **Q 一点没降（1893），T +6.4%**；
   用 `ixor_gf2_div` 直接写进 `q_i` → **Q 降到 1881，但语义 512/512 全错**
   （`ixor_gf2_div` 没有 `control` 形参，子步门控是承重的）。
   结论：**12 位（Q 的 0.63%，score ×1.015）被 API 挡住，其余 78 位在本算法内拿不掉。**

**建议：dqi 这一项不提交任何 Q 改动**（§5）。Q 的 2:1 兑换率是真的，但 dqi 的 Q 里没有 2:1 可换的东西；
真钱在 T（5,725,109），而 E3 已经把 T 的路线图铺好了。

各阶段的瞬态峰值（解析，实测吻合）：

| 阶段 | 瞬态 | 峰值 | 说明 |
|---|---:|---:|---|

## 2. 任务 2：四条点名路线的逐项评估

### (a) 余数显式存储（explicit remainder storage）

**它是什么**：`reg_b` 这个 73 字的辅助多项式数组，加上 `_shift_b_array_right`（每迭代把 b 的活动窗
整体右移一个槽）这套机制。**判据**：如果它是「每轮余数的副本」，那它应该有可回收的冗余。

**实测结论：否。见 §0.1 与 §3。** 占用率 95.7%（均值）/ 98.6%（含 A 的打包下界 = 144/146）。
一个「打包/紧凑表示」的收益上限是 24 量子比特（Q 的 1.27%，score ×1.026）。

**「就地更新」已经做了**：`sweep_positions` 本身就是
`reg_b[i] ^= q_i · reg_a[i]`（原地），`_shift_b_array_right` 用 cswap 滑窗而不是另开数组。
**没有第二份副本可删。**

**「不要数组、反向重算」**：可逆 EEA 的反向遍（`reverse_eea`）已经是「同一序列倒着跑」，
它需要的正是这两个数组的现场；要靠重算代替存储，等于每一步都从 S 重新推 r_{i-1} ——
复杂度从 O(n²) 变成 O(n³) 级。**✗ NO-GO（Q）。**

> ⚠️ 这条路线唯一还活着的形态，是把整个 key-equation 求解器换掉、让 ω 根本不被物化 ——
> 那已经不是「显式余数存储」了，见 §5.3。

---

### (b) 指针驱动 EEA 步（pointer-driven EEA steps）

**它是什么**：把物理搬动换成索引算术：
- `_swap_a_and_b`：整数组 cswap（892 个量子比特对）= **396,048 T = 全 T 的 6.92%**
- `_shift_b_array_right`：窗口滑动 cswap = **383,616 T = 6.70%**

**Q 影响：实测为零。** 这两处只分配 `swap_ctrl`（1 位）与 `nf + ctrl_nB`（3 位），
远在 90 位瞬态之下；删掉它们 `num_qubits` 不会动。

**T 影响：上限约 13.6%**（若两者都换成索引算术）。这是一条**纯 T 路线**，
应记到 E3/E5 的 T 账上，不是 Q 账。

**可行性提示（给 E5）**：`_active(cursor, i, lim)` 里 `lim` 是编译期常量，但除法扫描的
活动窗已经由量子 `n_A/n_a` 经 `_xor_threshold` 门控 —— 也就是说窗口本身就是量子驱动的，
把「偏移」并入阈值比较在结构上是通的。**✗ Q-NO-GO / ✓ T-候选（13.6%）。**

### (c) GF(2¹²) 多项式基运算  ← 唯一真的碰得到 Q 的一条

逐个基元实测瞬态量子比特（`n=70, b=12`）：

| 基元 | 保留的额外量子比特 | T |
|---|---:|---:|
| `ixor_gf2_mul(a, b → target)` | **0**（只有 target 本身） | 63 |
| `ixor_gf2_mul(..., control=q)` | 0 | 75 |
| `gf2_imul(const, target)` | 0 | **0**（线性映射 → 只有 CX/SWAP） |
| `init_gf2_inverse_with_scaffold` | 12（target）+ 48（链）= **60** | 315 |
| `init_gf2_inverse`（不留链） | 12 | 630 |
| `init_gf2_div_with_scaffold` | 12（商）+ 60（scaffold）= **72** | 378 |
| `init_gf2_div`（不留 scaffold） | 12 | 693 |
| `ixor_gf2_div` | **0** | 378 |

**除法基元是全场最大的单点瞬态（72 位），它就是 Q=1893 的成因。** 三条实测改法：

| 改法 | Q | ΔQ | ΔT | 语义 | 判定 |
|---|---:|---:|---:|---|---|
| `div_noscaffold`：`init_gf2_div`/`del_gf2_div` 代替 scaffold 版 | 1893 | **0.00%** | **+6.38%** | PASS 512/512 | ✗ 纯亏 |
| `div_ixor_into_q`：`ixor_gf2_div` 直写 `q_i`（诊断） | **1881** | **−0.63%** | −0.24% | **FAIL 512/512** | ✗ 语义不成立 |
| 保持现状 | 1893 | — | — | PASS | ✅ |

`div_noscaffold` 证明：**scaffold 的 60 位不是「保留」造成的浪费** —— 不留它，重算逆元时
内部峰值一样要 72 位，只是白付 6.4% 的 T。
`div_ixor_into_q` 证明：唯一能动的那 12 位（`ratio`）卡在
**`ixor_gf2_div` 没有 `control` 形参**上（实测 `TypeError: incompatible function arguments`，
签名只有 `lhs, rhs, *, target, field`）。子步门控 `c0_hc`/`c3_hc` 是承重的：
去掉它 512/512 全错。

> **给主办方/上游的最小补丁请求**：给 `ixor_gf2_div` 加一个 `control` 形参（对齐
> `ixor_gf2_mul` 已有的签名）即可拿到 **Q 1893 → 1881（0.63%），score ×1.015**。
> 这是本任务里**唯一一个真实、可立即落地的 Q 削减**，代价是一行 C++ 绑定。
> 在拿到它之前，用 kickmix 现有 API **无法**复现。

**结论：✓ 唯一碰到 Q 的路线；收益 ×1.015（被 API 锁住）；其余 78 位瞬态在本算法内不可动。**

## 3. 任务 3：优先攻 reg_b —— 876 位到底怎么来的

### 3.1 876 = 73 × 12，两个因子都钉死

- **12 = 域次数 b**，不可压（GF(2¹²) 元素就是 12 位）。
- **73 = `m_e = n_syndromes + 3`**，被 Chien/Forney 的布局**结构性地**钉住：
  Chien 把 σ（`t+1 = 36` 字）和 ω（`t = 35` 字）打包进同一个 `reg_b`，中间留 1 个空槽；
  σ 占 `[0, t]`，ω 占 `[m_e//2+1, m_e−1]`，而步长乘法器的排除条件
  `(m_e − 2 − k) mod 4095 ≠ 0` 恰好在 `k = m_e − 2` 处生效，等价于

  ```
  m_e//2 + t = m_e − 2   ⟺   ceil(m_e/2) = t + 2 = 37   ⟺   m_e ∈ {73, 74}
  ```

  `n=70, t=35` 时 `m_e = 73` 就是下限。**所以 73 不是「多留了 3 个字的余地」，
  而是 Chien 打包约束解出来的最小可行长度。**

### 3.2 它是「每轮余数副本」吗？—— 不是，实测

用 `src/e4/regb_liveness.py` 在**真电路**上（`DEBUG_PRINT` 探针，**零额外量子比特**，
电路宽度与门流与参考完全一致）逐迭代 dump `reg_a`/`reg_b` 的全部 146 个系数槽：

```
n=70, degree=12, 16 shots, 222 次前向迭代, 探针打在每次迭代开始（cswaps 之前）
  nnz_a  均值 72.29 / 最大 73  （占 73 槽 = 99.0%）
  nnz_b  均值 69.89 / 最大 72  （占 73 槽 = 95.7%）
  span_a 最大 73, span_b 最大 73
  打包下界 max(nnz_a + nnz_b) = 144   （固定分配 146）
```

原始槽值样本（`n=10`, 1 shot，`it` = 前向迭代号）：

```
it=  0  A=[0x1, 0x0, 0x0, 0xf1e, 0xa00, 0xaf2, 0xe5a, 0x940, 0xc69, 0xd56, 0x39a, 0xe3, 0x4cd]
        B=[0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x2]
it= 20  A=[0xd4b, 0x7b4, 0x6e8, 0x4a7, 0xbd7, 0xdb3, 0xc08, 0x4b4, 0x35f, 0x171, 0x83, 0x363, 0x6f0]
        B=[0xfa8, 0x30d, 0x286, 0x0, 0x0, 0x0, 0x776, 0x436, 0xe44, 0xdd2, 0x6f6, 0x3f8, 0x0]
it= 41  A=[0x301, 0x2e3, 0x693, 0xdc2, 0x30f, 0x75d, 0xd11, 0x0, 0x0, 0x71e, 0x8b8, 0xfed, 0xa41]
        B=[0x5ba, 0xe6b, 0x16b, 0x63c, 0xb98, 0x6da, 0x0, 0x0, 0x3aa, 0x9ee, 0xa0f, 0x809, 0xfd6]
```

B 在迭代 0 是一个单项式（1 个非零字，度数在高位），随后迅速变成密实的余数多项式；
到 it≥8 之后 A、B 都是密实的、随机外观的 GF(2¹²) 系数序列。

**「度数之和」不变式也查了，不成立**：`(deg_a+1) + (deg_b+1)` 的最大值是 **146 = 2·m_e**，
在 3552/3552 个 (迭代, shot) 组合上全部违反 `≤ n+2`。原因是可逆 EEA 必须**同时**持有
上一轮余数 r_{i−1} 与当前余数 r_i，两者度数都可逼近 n。**这不是浪费，这是可逆性的价钱。**

### 3.3 定量：更紧凑的表示到底能省多少

| 方案 | 省下的量子比特 | Q | score 倍率 | 判定 |
|---|---:|---:|---:|---|
| 打包 A/B 到单一数组（用实测下界 144 槽） | 2 字 = **24** | 1869 | ×1.026 | 理论上限，工程上是 Chien 布局重推 |
| 把 `reg_b` 缩到 (σ+ω)=71 字 | 2 字 = **24** | 1869 | ×1.026 | 同上（`reg_b` 已经是 73 字） |
| 「不留余数、反向重算」 | 73 字 = 876 | ~1017 | 需 T 代价 | 见 §5.2：O(n²)→O(n³)，✗ |
| **合计可动** | **≤ 24** | ≥ 1869 | **≤ ×1.026** | |

**结论：reg_b 的 876 位里，可以证明「不是必需」的部分 ≤ 24 位（1.27%）。**
项目里原先假设的「876 是 Proos–Zalka padding」不成立；把 876 视作可回收资源会白白吃掉几周。

## 4. 任务 4：最小可验证实验（实测数字）

**实验选点**：既然 §2/§3 说「瞬态是唯一靶子、reg_b 不可动」，最小实验就取
**代价最小、能一次讲清全部约束**的那一组：对 EEA 除法瞬态和 Chien 逆元瞬态各做一次去 scaffold 替换，
外加两次反证。

**验证协议**（`src/e4/semantic.py`）：直接复用**官方 verifier 的**采样与寄存器校验
（`sample_shots` / `optimal_dqi_weights` / `validate_registers` / `to_bits`），
在 `m_chien=280, n=70, b=12` 上跑三条件契约（综合征还原 / 非综合征量子比特回 |0⟩ / 相位等于
`(−1)^Σ popcount(e_j ∧ M_j)`，`e` 是**实际种入**的错误字）。
构建 ≈ 4.0 s，512 shot 仿真 ≈ 3.2 s，2048 shot ≈ 12.7 s。

### 4.2 反证 #1：`div_ixor_into_q` —— `ratio` 那 12 位拿得到、但语义不成立

`ixor_gf2_div` 实测 **0 额外量子比特、378 T**（与 scaffold 版同价），把商直接 XOR 进 `q_i`
就能绕过 `ratio` 寄存器 → **Q 1893 → 1881**。但它的签名里没有 `control`：

```python
def ixor_gf2_div(self, lhs, rhs, *, target, field=None) -> None   # 实测无 control 形参
```

丢掉子步门控后 **512/512 shot 的综合征还原全部失败**（`value_errors=512`）。
**这同时是两个结论**：(i) 12 位是真的可回收；(ii) 用现有 API 拿不到。

### 4.3 反证 #2：去 scaffold 不省量子比特

`div_noscaffold` 与 `chien_inv_noscaffold` 的 **ΔQ 都是 0.00%** —— 语义正确、T 反而变贵。
这直接排除了「scaffold 的 60/48 位是可以不保留的」这条最直觉的想法：
不留它，重算时内部峰值照样要那么多。**瞬态是基元自身的最小工作集，不是我们的记账习惯。**

### 4.4 反证 #3：`logm_minus1` 是「看起来很赚」的陷阱 —— **必须标风险**

`logm = m.bit_length() + 1 = 8` → 改成 `7`，Q 1893→1888，T −0.38%，score ×1.0091，
而且本地 **2048 shot（官方分布）+ 1024 shot（最大权重 k=n/2 压力）全部 0 错误**。
看起来是一个免费的小便宜。**它不是。**

用 §3.2 的探针把 8 位和 7 位两种元数据寄存器宽度的调度轨迹逐迭代比对
（`n=70`，同一批综合征种子）：

```
field   max(8bit)  max(7bit)   iters differing   iters 8bit>127
n_A           253        125              180/222        180   first_diff=it42
n_B           253        126              222/222        182   first_diff=it0
n_a           148        125              222/222         36
n_b           148        125               37/222         33
n_q             8          9               33/222          0
```

**n_B 从第 0 次迭代起就已经不一样，n_a/n_B 在 222 次里全部不同。**
也就是说 `logm_minus1` **不是等价优化，是另一个算法**：8 位寄存器的余数确实会到 253（2¹⁸ 上界之外），
算法消费的是 `n_A mod 2⁸` 这个余数，改模数就换调度。2048+1024 shot 全过**不能**推出
102,400 shot 全过 —— 参考解零失败的证据（`eps₊ = 8.66e-4` 的统计地板）**不覆盖一个不同的调度**。

**判定：✗ REJECT。收益 ×1.0091，风险是「在未测到的 shot 上破坏零失败率」，
而零失败率是硬要求（`eps₊ < 1/16`，参考 8.66e-4）。用 0.9% 换掉统计地板是纯亏。**

### 5.3 硬下界与「30% 瘦身」的真实门槛

- **S 的 840 位是契约硬底线。** `verify_submission_dqi.py` 要求寄存器恰好是
  `S0..S69`（量子，宽 12）+ `E0..E_{m−1}`（经典），且每 shot 结束后
  **S 必须还原、其它量子比特必须回 |0⟩**。→ **Q ≥ 840**。
- **物化 σ 与 ω 的解码器：Q ≥ 840 + (36+35)×12 = 1692。**
  （σ 的次数 ≤ t = 35 → 36 个字；ω 的次数 ≤ t−1 = 34 → 35 个字；
  S 活着的时候它俩必须同时在场。）参考实现 1893 = 1692 × 1.119 —— **只高出硬底线 11.9%**，
  **全部榨干也才 ×1.252。**
- **用户设想的 Q ≈ 1325（−30%）落在哪里？**
  （纯 Q 因子 = (1893/1325)² = **×2.04**；任务书里的 ×1.70 应当已经算进了 T 的变化。）
  `1325 − 840 = 485` 位工作集 ≈ **40 个字**。一个必须持有 σ(36 字)+ω(35 字)=71 字的解码器
  **在信息论上做不到**。要落到 1325，唯一的路是**不再物化 ω** —— 直接用 σ 和 S
  逐位置算 Forney 的 `ω(α^{-j})`（例如对 S 做 Horner 扫描在线求值）。那样下界松到
  `840 + 36×12 = 1272` + scratch ≈ **正是 1325 所在的位置**。
- **所以「Q −30%」= 换 key-equation 求解器 + 换 Chien/Forney 求值方式**，
  而不是给现有电路减肥。这是一次研究级重写（`APPROACH.md` §E5 估 2–4 周）。
- **而且它多半会把 T 变贵**：现在 Chien 循环里 ω 的求值是 `gf2_imul(const)`（**0 T**，
  因为 4095 个位置的 α^{-ij} 已经预计算成常数），换成在线卷积 `ω_i = Σ_k S_{i-k}σ_k`
  就是每位置 35×35 项乘加。要让这次重写净亏回 σ+ω 下界的 ×1.252，T 只需涨 **77%**；
  这个门槛不算高。

### 5.4 dqi 的真钱在哪

`score = R·Q²·T`，`R` 是地板、`Q` 只剩 ≤1.3% 可动 —— **剩下的全在 T 上**：

| T 组成（E2b/E3 实测） | T | 占全场 T | E4 复核 |
|---|---:|---:|---|
| 全场 | 5,725,461（静态） | 100% | — |
| EEA | 4,288,116 | 74.9% | ✅ |
| ├ EEA `mul` 扫描 | 2,430,600 | 42.5% | ✅（E3 已否掉静态调度：p = 8.887e-3，NO-GO） |
| ├ `_swap_a_and_b` cswap | 396,048 | 6.9% | **E4 新结论：指针驱动可回收，且与 Q 无关**（§2b） |
| ├ `_shift_b_array_right` cswap | 383,616 | 6.7% | **同上** |
| └ `init_gf2_div_with_scaffold` | 335,664 | 5.9% | — |
| Chien/Forney | 1,437,345 | 25.1% | Montgomery k=4 上限 ×1.033 |

**E4 给 E5 的移交**：把 (b) 指针驱动 EEA 当作**纯 T 项目**做（上限 −13.6% T ⇒ ×1.16 score），
不要再把它当 Q 项目；Q 侧只有「上游给 `ixor_gf2_div` 加 control」这一件小事值得提。
